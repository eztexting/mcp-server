Overview

EZTexting MCP exposes 42 tools — send SMS/MMS, manage contacts and groups, run workflows, fetch reports, manage webhooks, query account state.

Prefer remote. If your client speaks Streamable HTTP MCP, point it at https://mcp.eztexting.com/mcp directly. No npm, no Node, no child process, faster startup, auto-updates server-side. Use the local stdio bridge only when the client doesn't support remote yet.

1. Remote — Streamable HTTP recommended

Claude.ai, ChatGPT, Claude Desktop, Claude Code, Cursor 0.46+, VS Code 1.99+, Windsurf, Cline 3.0+.

Endpoint: https://mcp.eztexting.com/mcp. OAuth 2.1 PKCE auto-discovered.

2. Local — stdio bridge

Fallback: clients without native remote MCP support, air-gapped envs, or proxy quirks.

Runs npx -y @eztexting/mcp-server as child process. Tokens cached in ~/.mcp-auth/.

Prerequisites

  • EZTexting account — sign in at app.eztexting.com.
  • Browser — OAuth 2.1 PKCE pops on first connect.
  • Node.js 20+ — only if you fall back to the local stdio bridge. Verify: node -v.

  4. URL:

First run / OAuth

Remote connection

  1. Client makes first request to https://mcp.eztexting.com/mcp.
  2. Server returns 401 + WWW-Authenticate hint with discovery URL.
  3. Client opens browser to https://mcp.eztexting.com/oauth2/authorize?....
  4. Sign in → approve scope → redirect back to client.
  5. Client stores access + refresh tokens. Auto-refresh on expiry.

Token storage location is client-managed (Claude.ai / ChatGPT keep tokens server-side; Claude Desktop / VS Code in OS keychain).

Local stdio bridge

  1. Client launches npx -y @eztexting/mcp-server.
  2. Browser opens to https://mcp.eztexting.com/oauth2/authorize?....
  3. Sign in → redirect to local listener → tokens written to ~/.mcp-auth/mcp-remote-<version>/<hash>/.
  4. Subsequent launches reuse cached tokens (auto-refresh).

Force fresh sign-in (local bridge)

rm -rf ~/.mcp-auth/mcp-remote-*

One <hash> directory per distinct upstream URL. Sub-server bridges + unified bridge each get their own. For remote connections, revoke via your client's connector UI.

Troubleshooting

Server won't start

  • node -v — need 20+.
  • Test the bridge directly: 
    npx -y @eztexting/mcp-server
  • Behind proxy? Set HTTPS_PROXY in the client's MCP env block.

Browser never opens

  • Check default browser is set.
  • Headless / SSH session: copy the printed URL into a browser on a workstation that can reach localhost:<port> on the same machine.

Tools not visible

  • Fully quit + relaunch the client (Claude Desktop & Cursor cache server lists).
  • Check the client's MCP log panel.
  • Confirm OAuth completed: directory exists under ~/.mcp-auth/.

401 / token expired

rm -rf ~/.mcp-auth/mcp-remote-*

Restart the client. Browser will pop again.
