Overview

EZTexting MCP exposes 42 tools — send SMS/MMS, manage contacts and groups, run workflows, fetch reports, manage webhooks, query account state. There are two ways to connect:

Local stdio bridge

For clients that only speak stdio MCP (Claude Desktop, Claude Code, Cursor, VS Code, Cline, Windsurf, Zed).

Runs npx -y @eztexting/mcp-server as a child process. Browser pops on first run for OAuth. Tokens cached in ~/.mcp-auth/.

Native Streamable HTTP

For clients that speak remote MCP directly (Claude.ai web, ChatGPT custom connectors, future-native clients).

Point straight at https://mcp.eztexting.com/mcp. No npm, no Node, no bridge.

Prerequisites

  • EZTexting account — sign in at app.eztexting.com.
  • Node.js 20+ — only for local stdio bridge. Verify: node -v.
  • Browser — first run pops OAuth 2.1 PKCE flow.

Claude Desktop (local)

Edit your config file, then fully quit + relaunch Claude Desktop.

Config file location

OSPath
macOS~/Library/Application Support/Claude/claude_desktop_config.json
Windows%APPDATA%\Claude\claude_desktop_config.json
Linux~/.config/Claude/claude_desktop_config.json

Config (unified — all 42 tools)

{
  "mcpServers": {
    "eztexting": {
      "command": "npx",
      "args": ["-y", "@eztexting/mcp-server"]
    }
  }
}

Verify: open Claude Desktop → Settings → Developer → MCP Servers. eztexting should be listed and "running".

Claude Code (local CLI)

Two ways: CLI command or edit settings JSON.

CLI (recommended)

claude mcp add eztexting -- npx -y @eztexting/mcp-server

Scope to user (global) or project:

claude mcp add --scope user eztexting -- npx -y @eztexting/mcp-server
claude mcp add --scope project eztexting -- npx -y @eztexting/mcp-server

Manual config

Edit ~/.claude.json (user scope) or .mcp.json in repo root (project scope):

{
  "mcpServers": {
    "eztexting": {
      "command": "npx",
      "args": ["-y", "@eztexting/mcp-server"]
    }
  }
}

Verify: claude mcp list

Claude.ai (remote, no install)

Claude.ai supports remote MCP servers via the Connectors UI. No bridge, no Node.

  1. Go to claude.ai → Settings → Connectors.
  2. Click Add custom connector.
  3. Name: EZTexting
  4. URL: 
    https://mcp.eztexting.com/mcp
  5. Save → Click Connect → OAuth pop-up → sign in.

Available on Pro / Team / Enterprise plans.

VS Code (GitHub Copilot Chat — Agent Mode)

VS Code 1.99+ supports MCP natively in Copilot Chat agent mode.

User config

Command palette → MCP: Open User Configuration. Add:

{
  "servers": {
    "eztexting": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@eztexting/mcp-server"]
    }
  }
}

Workspace config

Create .vscode/mcp.json in repo root (same shape).

Remote variant (no Node needed)

{
  "servers": {
    "eztexting": {
      "type": "http",
      "url": "https://mcp.eztexting.com/mcp"
    }
  }
}

Open Copilot Chat → switch to Agent mode → tools list now shows eztexting.

Cline (VS Code extension)

  1. Open Cline panel in VS Code.
  2. Click the MCP Servers icon (top of panel).
  3. Click Configure MCP Servers → opens cline_mcp_settings.json.
  4. Add:
{
  "mcpServers": {
    "eztexting": {
      "command": "npx",
      "args": ["-y", "@eztexting/mcp-server"],
      "disabled": false,
      "autoApprove": []
    }
  }
}

Save. Cline auto-restarts the server. Refresh the MCP panel if tools don't appear.

ChatGPT (remote)

ChatGPT supports remote MCP via custom connectors (Plus/Pro/Team/Enterprise — Developer mode).

  1. Settings → Connectors → Advanced settings → enable Developer mode.
  2. Connectors → Create.
  3. Name: EZTexting
  4. MCP Server URL: 
    https://mcp.eztexting.com/mcp
  5. Auth: OAuth (auto-discovered).
  6. Save → Connect → sign in.
Custom connectors run with full tool access. Review the tool catalog before approving destructive actions (e.g., contact_delete, contact_group_delete).

Native Streamable HTTP (any client)

Any client speaking the MCP Streamable HTTP transport can connect direct:

https://mcp.eztexting.com/mcp                    # unified — all 42 tools
https://mcp.eztexting.com/mcp/messaging           # send/list messages, templates, conversations
https://mcp.eztexting.com/mcp/contacts            # contacts, groups, custom fields
https://mcp.eztexting.com/mcp/workflows           # workflow CRUD + templates
https://mcp.eztexting.com/mcp/admin               # account, credits, webhooks, stats

OAuth 2.1 PKCE discovery via /.well-known/oauth-authorization-server. Bearer token sent as Authorization: Bearer <token>.

Sub-servers (narrow scopes)

Use the unified /mcp endpoint by default. Pick a sub-server when you want a smaller tool catalog or a separate identity.

Stdio bridge — pin one sub-server

{
  "mcpServers": {
    "eztexting-messaging": {
      "command": "npx",
      "args": ["-y", "@eztexting/mcp-server", "--server", "messaging"]
    }
  }
}

First run / OAuth

  1. Client launches npx -y @eztexting/mcp-server.
  2. Browser opens to https://mcp.eztexting.com/oauth2/authorize?....
  3. Sign in to EZTexting → approve scope.
  4. Redirect back to local listener → tokens written to ~/.mcp-auth/mcp-remote-<version>/<hash>/.
  5. Subsequent launches reuse cached tokens (auto-refresh).

Force fresh sign-in

rm -rf ~/.mcp-auth/mcp-remote-*

One <hash> directory per distinct upstream URL. Sub-server bridges and the unified bridge each get their own.

Troubleshooting

Server won't start

  • node -v — need 20+.
  • Test the bridge directly: 
    npx -y @eztexting/mcp-server
  • Behind proxy? Set HTTPS_PROXY in the client's MCP env block.

Browser never opens

  • Check default browser is set.
  • Headless / SSH session: copy the printed URL into a browser on a workstation that can reach localhost:<port> on the same machine.

Tools not visible

  • Fully quit + relaunch the client (Claude Desktop & Cursor cache server lists).
  • Check the client's MCP log panel.
  • Confirm OAuth completed: directory exists under ~/.mcp-auth/.

401 / token expired

rm -rf ~/.mcp-auth/mcp-remote-*

Restart the client. Browser will pop again.
